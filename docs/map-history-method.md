# 配置履歴の根拠と期間生成

## 出典

- みんレポのゴッサムシティ公開一覧を起点として、掲載されている営業日・詳細ページURLを取得する。
- 各営業日の全台表から「台番号」「機種名」だけを取り出す。店名・営業日・全台表の台数と対応づけた番号の件数を確認する。
- 2026-09-10については、前版で確認済みの310台の対応も引き継ぐ。
- DMMぱちタウン店舗告知から新台・増台・入替・配置変更に関する告知日と、本文に明記された実施日を保存する。画像からの推測だけで実施日や台番号を確定しない。
- 稼働・差枚・設定推測の観測データには自動で混ぜない。

元ページの見出し・日付・台番―機種の事実を参照する。記事本文を転載するための機能ではない。出典・収集日・未取得状況は履歴ファイルに残る。

## 比較と変更日

営業日順に、台番号ごとの機種名を比較する。基本は全角半角と空白だけを正規化し、機種の世代や型名は保持する。310番号の機種が揃わない表は、欠けた番号の撤去と解釈せず未確認日にする。

明示的な表記差ルールは以下の3件だけに限定する。元の掲載名、対象台番号、適用日、出典、判断理由を `labelNotes` に残し、画面から確認できる。

- 「LB ヱヴァンゲリヲン～約束の扉～」は「LBパチスロ ヱヴァンゲリヲン～約束の扉～」の名称省略として統合。[メーカー販売名](https://www.sankyo-fever.jp/collection/983/)と照合。
- 「L エウレカセブン4 HI－EVO KX」は「スマスロ交響詩篇エウレカセブン4 HI-EVOLUTION」の型式名表記として統合。[販売名・型式名](https://opt.p-world.co.jp/machine/database/10011)、[メーカー発売告知](https://www.sammy.co.jp/japanese/news/detail/?id=121)。
- 2024-04-26以降の93–95番台に限り、「ジャグラーガールズ」と「ジャグラーガールズSS」の反復記載を表記差候補として比較上統合する。**これは推定**。SSへの同定を確定とは扱わず、該当期間・台番号に推定注記を表示する。[SSのメーカー資料](https://www.kitadenshi.co.jp/products/2024/jgss/)は名称・発売世代の確認資料であり、この店の個別台を同定する証拠ではない。

型番の世代が異なる機種名を一律に消すルールは設けない。掲載表の修正と実際の入替を区別できないものは、割当表の変更として保存し、筐体移動が証明されたとは表示しない。

前日の全台表と当日の全台表の割当が異なれば、当日を機種割当変更の境界として保存する。公開日は翌日でも、営業日を境界に使う。開始日は含み、終了日は含まない。ここで確定するのは公開表上の割当変更日であり、個々の筐体の物理移動そのものではない。

機種別台数の増減だけでは、台数が変わらない配置移動を見落とす。比較は全台の割当で行い、各変更台の以前・以後の機種と、機種別の台数増減を記録する。

同じ割当が再確認されたら同じ期間にまとめる。配置が異なるときだけ期間が増える。期間内に未取得日がある場合は、その日付の範囲も保持する。

## 欠落と確度

変更の前後に欠けた日があると、その間のどの日に変わったかはログだけでは決まらない。その期間は「変更日未確定・初確認日」と表示し、最後に旧配置を確認した日と新配置を初確認した日を並べる。

日付指定による照会では、選択日に全台表を読めているかも確認する。期間の範囲内でも未取得・未掲載の日は、その日の配置を確定済みとして返さない。

同日の入替告知は根拠リンクとして表示する。ログの欠落中に告知があれば「変更候補区間の告知」として関連づけ、実施日がない告知は掲載日しか確定していない資料として扱う。告知だけから、明記されていない台番への割当や、全ての台が同時に移動したことを推定しない。台番号表に個体識別情報がないため、同一機種の個々の筐体移動は確定できない。表記変更が機種変更と区別できない場合も、元の表記と出典を保持する。

## 物理マップ

期間を切り替える機種マップは台番号順の固定セルで表示する。公開フロア図は別の参考画像として表示する。台番号の正確な物理座標を確認できていないため、座標ピン、島の向き、隣席関係を作らない。

## 更新用ツール

`tools/collect_map_history.py` は明示的に実行する収集ツール。通常起動時にネットワーク収集は行わない。Python標準ライブラリを使用し、WindowsではプラットフォームのHTTPクライアントも選択できる。キャッシュされた事実表から `--offline` で履歴を再生成できる。

収集は1秒以上の間隔を設ける。アクセス制限・認証要求・CAPTCHA・サイトの閲覧制限を回避する機能は持たない。アプリ更新用の履歴ファイルには、取得できた表だけを採用する。
