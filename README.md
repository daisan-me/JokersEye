# Joker's eye 1.3.1

ゴッサムシティの観測データと店内配置を研究する、Windows / macOS 共通のローカルアプリです。

## ダウンロードして使う（コマンド不要）

Python のインストールもコマンド操作も不要な、ダブルクリックで起動するパッケージを GitHub が自動で作ります。

1. GitHub のリポジトリ画面で「Actions」→「package」を開き、使いたいブランチの最新の実行（緑のチェック）を選びます。
2. 画面下の「Artifacts」から、Windows は `JokersEye-<版数>-windows`、macOS は `JokersEye-<版数>-macos` をダウンロードします。
3. Windows：ZIP を右クリック →「すべて展開」し、`Joker's eye` フォルダーの `Joker's eye.exe` をダブルクリックします。「Windows によって PC が保護されました」と出た場合は「詳細情報」→「実行」を選びます。
4. macOS：ダウンロードした ZIP を開き、中の `Joker's eye.zip` をダブルクリックして出てきた `Joker's eye.app` を「アプリケーション」へ移します。初回に開けない場合は「システム設定」→「プライバシーとセキュリティ」の「このまま開く」を選びます。

Windows には Microsoft Edge WebView2 Runtime が必要です（Windows 11 には標準で入っています）。データの保存先は下の「保存先・更新」と同じで、以前の版のデータをそのまま使います。心配な場合は、起動前にエクスプローラー／Finderで保存先フォルダーをコピーしておきます。コード署名は未対応のため、上の確認画面が出ます。

## バージョン（ブランチごとの版を試す）

左メニューの「バージョン」で、GitHub上の各ブランチの版を一覧し、選んだ版をダウンロードして別ウィンドウで起動できます。コマンド操作は不要です。

- 一覧には、各ブランチで自動テスト（`package`）に通った最新の版を表示します。版数・コミット・作成日時・サイズと、新しい版を作成中か、作成に失敗したかも表示します。
- 「ダウンロードして起動」を押すと、進み具合を画面に表示しながら取得・展開し、起動します。一度ダウンロードした版は「起動」ですぐに開けます。
- 試す版は、初めて起動するときに本番データをその版専用のフォルダー（データフォルダー内の `versions`）にコピーして使います。試した版でデータが変わっても、本番データは変わりません。試した版で取得したデータは本番に反映されません。
- 試用中のウィンドウは、右上と左下に紫色でブランチ名とコミットを表示します。試用中の版からは、ほかの版の操作はできません。
- 「このPCにある版」の「削除」で、その版とコピーしたデータを消せます。本番データは消えません。
- 初回だけ GitHub のトークン（対象リポジトリの「Actions」読み取り権限のみ）を画面から登録します。手順は画面に表示されます。トークンはこのPCのデータフォルダーにだけ保存し、GitHub以外には送りません。
- 左下には、いま開いている版のブランチ名とコミットを常に表示します。

## セットアップと起動

必要なもの：Python 3.10 以上（推奨 3.12。`.python-version` 参照）と、OS 標準の WebView（Windows 10/11 は Microsoft Edge WebView2 Runtime、macOS は WKWebView で追加インストール不要）。Windows で WebView2 Runtime がない場合は[Microsoft公式配布ページ](https://developer.microsoft.com/microsoft-edge/webview2/)から Evergreen Runtime を入れてください。

```bash
git pull
python launch.py
```

Windows で Python が `python` で起動しない場合は `py launch.py` を使います。初回だけ `.venv` を作り `requirements.txt` の依存（pywebview）をインストールします。2回目以降はすぐに起動します。Windows ではコンソールなしで開く `launch.pyw` をダブルクリックしても起動できます（初回は一度 `python launch.py` で依存を入れてください）。

macOS ではデスクトップ用のアプリを作れます：`python3 tools/make_mac_app.py`（`Joker's eye.app` を作成。このリポジトリのフォルダーを動かしたら再実行してください）。

アプリの本体は `app/server.py`（ローカルサービス）と `app/desktop.py`（専用ウィンドウ）です。ブラウザーで直接確認したい場合は `python app/server.py --open --port 0` でも起動できます。開発者向けの診断は `python app/desktop.py --diagnostics <出力ファイル>` です（接続表示・版数・台番号マップの描画を確認して終了します）。

左下の「アプリを終了」またはウィンドウの×で専用サーバーも停止します。最小化中も接続を維持します。二重起動時は既存ウィンドウを手前に表示します。起動ごとに空きローカルポートと独立したセッションを使用します。外部リンクだけを標準ブラウザで開きます。

1.0 からの変更点は [CHANGELOG.md](CHANGELOG.md) を参照してください。1.0 の Windows 専用 EXE 版（C# ランチャーと同梱 Python）は git の履歴（タグ `v1.0.0-windows-exe`）に残しています。保存先が同じため、1.0 のデータはそのまま引き継がれます（Windows）。

初回起動時の稼働・差枚の観測データは0件です。別途、公開フロア図と、みんレポの公開日別台番表から作った機種配置履歴を同梱しています。対象の公開一覧は2023-04-27〜2026-09-29です。取得できた日数・期間数・最終確認日・未取得日は「機種マップ」に表示します。全台表を読めない日を配置確定済みとして補完しません。

店内マップは、現地確認済みのNumbered map 1.4 ex.Is-IDの固定配置を使用します。全310台の四角の位置・角度・台番号、32島の構成と内部Is-IDは変更せず、Is-IDの文字は表示しません。台番号で履歴と結び付け、期間タブや日付検索で各時期の機種を表示します。固定図を共通の土台として使うため、過去時点の壁・島形状まで確認したものではありません。

1.1.1では四角をすべて一律1.25倍に拡大し、重なっていた5台だけ島の中心から外向きに表示調整しています。この例外は別ファイルに記録し、上記の正本の位置は未変更です。台番号・角度・内部Is-IDは固定。黄色の変更マークの半径は以前の2倍。拡大・ドラッグは描画タイミングに集約し、画面外の台の描画を省略します。

1.2.0では、データ管理に11列の「基礎データシート」（CSV）を追加しました。2026-10-07にCSVは廃止し、同じ11列の一覧はデータベース（GDB）から直接表示しています（下記「GothamDataBase（GDB）」）。

四角は既存のデザインを流用し、機種マップではジャグラー系統を高彩度、その他を低彩度で色分けします。外壁はUI共通の青緑。クリック・キーボード選択、台番号・機種検索、変更台の強調、台番号別の履歴は保持しています。拡大縮小は＋／−、倍率スライダー、Ctrl＋ホイールで操作し、拡大中はドラッグで移動できます。「選択台へ」で選択中の台を拡大、「全体表示」で戻ります。期間切替でもカメラと選択台を保持します。記録にない機種は「未掲載」とし、現在の店舗とのリアルタイム同期は未実装です。

## ジャグラー設定推測機

左メニューの「ジャグラー設定推測機」から機種を選び、「設定別スペック」「ぶどう逆算機」「設定推測機」を切り替えます。北電子公式一覧の47製品・パネルを同梱し、設定1〜6のBB確率、RB確率、合成確率、出玉率を表示します。6号機と過去の5号機は区別しています。各表から公式スペック・配当表へ移動できます。旧5製品の公式表にないBB/RB別の値は「未掲載」です。

1.3.0はユーザー指示に従う関数準備版です。ぶどう逆算・設定別確率の関数と入力欄を用意していますが、実行ボタンは無効で結果は「未計算」です。入力や機種切替で計算は実行しません。既存の観測への推測の適用も行いません。関数の入力、逆算条件、推測の定義は[docs/juggler-estimators.md](docs/juggler-estimators.md)を参照してください。

1.3.1では、追加の検算指示に従い、全47製品・パネルの関数を合成テストデータだけで実行検証しました。992件合格、計算モジュールの関数・行・分岐カバレッジ100%。入力検証と数値安定性の不具合を修正しています。画面の実行ボタンは無効のままです。[検証記録](docs/juggler-test-results.md)を参照してください。

## 公開データのスクレイピング

取得は「データ管理」の「公開データを取得する」パネルだけで行い、結果はGDBに保存して、同じ画面の「登録した観測」とGDBの一覧で確認します。「本日までの分を更新」は、GDBに記録されている最後の日から日本時間の本日までを取得します（記録がなければ2024/03/01から）。最後の日に揃っている記録は取り直さず、BB/RBが空なら補完します。前回の時点で未掲載だった最後の日より後の日は、もう一度確認します。「期間を指定して取得」は、開始日・終了日の範囲で、記録がない日は全台表とBB/RBを取得し、BB/RBが空の日はそこだけ補完します。全期間を回す前に1週間ほどで試すときにも使います。重複は日付・台番号の主キーで防止します。終了や通信失敗までの結果はGDBに残り、次回再開できます。

アプリに組み込んだ通常のWebView（Windows は WebView2、macOS は WKWebView）で公開ページを読みます。この取得ブラウザーはアプリ本体と同じプロセスで動き、データフォルダーの `WebView2` に Cookie を保存します（公開サイトの確認用スクリプトが通るために必要です）。日別レポートを先に開き、その本文にある正規の全台データ一覧リンクをたどります。日付・店舗名・掲載年月日・台番号を検証してから保存します。取得ブラウザーは画面に表示され、閉じると取得を停止します。OpenAI API・Codex・AIモデルは呼び出さないため、通常の更新でAIトークンは消費しません。全台表は逐次取得で1秒以上、BB/RBの機種別ページは3秒以上の間隔を設けます。HTTP 200の空ページだけは3秒待って通常の再読み込みを一度行います。401/403/429、認証・CAPTCHA等に対して回避処理は行いません。データ提供サイトの変更や閲覧制限がある場合、取得できるとは保証しません。

BB・RBはいつも取得します。全台一覧で機種・台番号・G数・差枚・出率を保存した後、公開ページ内の実在リンクをたどって機種別の台番表からBB/RB・合成を補完します。1台設置機種等で必要なら個別台の分離された当日表も使い、過去10日表や平均行を当日データに混ぜません。対象台のBB/RB表が揃うまで待ち、店舗・日付・掲載年月日・台番号・G数を照合します。全角スペースを含む機種リンクにも対応しています。

取得中断後は揃っている機種をスキップして再開できます。既存の全台表のG数・差枚・出率、保存済みBB/RBは保持します。機種別表の差枚・出率が「-」でも、全台一覧の実値を消しません。0回は有効な実値、空欄は未取得・欠測です。BBとRBが両方数値で保存されて初めて、その台のBB/RB取得完了と判定します。出典はGDBの `bonus_source_url` 列に残します。全台の番号網羅とBB/RBの網羅は別に表示します。

HTTP 200の空ページは通常の再読み込みを一度試し、それでも空なら当該機種を後回しにします。公開レポートへ戻って再訪し、必要なら実在する個別台リンクを使用します。失敗した日・機種は不足として残します。401/403/429等は停止し、認証や確認画面の回避は行いません。公開されない値の推定・0補完は行いません。

取得結果はすべてGDB（下記）に保存し、CSVファイルは作りません。公開一覧にない日を休業日や全台0とは断定しません。既存の機種名だけのキャッシュは数値データ取得済みとは扱いません。

## GothamDataBase（GDB）

台データは、データフォルダーの `GothamDataBase.sqlite`（GDB）1ファイルだけで管理します。CSVファイルの保存・書き出し・取り込みは行いません。1.3.1までの `jokers-eye.sqlite3` は、新しい版の初回起動時に自動で `GothamDataBase.sqlite` へ名前を変えて引き継ぎます。

「データ管理」の「GothamDataBase（GDB）」は閲覧専用で、2024-03-01以降の記録を `日付、曜日、台番号、機種、ジャグラーかジャグラーじゃないか、ゲーム数、BB数、RB数、合成、差枚、出率` の11列（1行＝その日のその台）で表示し、日付・月・曜日・機種・ジャグラー判定・ゲーム数以上・差枚以上・合成1/n以下・出率以上で絞り込めます。取得が終わると自動で表示を更新します。

過去日のBB/RBは「期間を指定して取得」で補完します。BBまたはRBが空の保存済み日だけ取得し、空のBB・RB・合成だけ更新します。取得済みの機種は再巡回しません。停止しても途中までは保存され、再実行で不足だけを取得します。

## マップ操作

1. 左メニューの「店内マップ」を開くと、最新の確認済み配置を表示します。
   同じ画面の「台番号マップ／機種マップ」で表示を切り替えます。台番号マップは番号だけの共通色表示、機種マップは機種名と機種別の色を表示します。期間・選択台を引き継ぎ、両表示の検索条件はそれぞれ保持します。表示位置は現地確認済みの固定図と、上記の重なり回避用表示調整を使用します。
2. 横並びの期間タブを押すか、期間名の `▽` から別の期間を選択します。期間は実際に台番への機種割当が変わった記録から生成しています。例として示された日付は境界に使っていません。
3. 「日付から探す」で確認したい日を選べます。その日の記録があれば該当期間の機種マップへ切り替わり、未取得・未掲載日なら「未確認」を表示します。
4. 台番号を押すと、その番号に割り当てられていた機種の変遷と出典を表示します。履歴の期間名から、その当時のマップへ戻れます。
5. 「変わった台だけ強調」と「配置変更」の一覧で、変更前後の機種・台数増減を確認できます。機種名・台番号による検索も使えます。

期間は開始日を含み、終了日を含みません。前日と当日の台番表が揃う変更日は「前日との差分で確認」、欠落を跨ぐ差分は「変更日未確定・初確認日」と表示します。同じ配置が再確認された場合は新しい期間を増やさず、欠けた日を保持します。機種マップの期間が表示されることと、期間中の全日を確認できていることは別です。

DMMぱちタウンの新台・増台・入替告知も収録し、確認した実施日と同じ配置変更に出典リンクを付けています。告知の掲載日だけが分かる場合は実施日に置き換えません。同じ機種の個体番号は公開表にないため、ここでいう台移動は台番号への機種割当の変化です。

掲載名の省略・型式名表記は、明示した個別ルールで比較上統合します。93–95番台の「ジャグラーガールズ／SS」の反復記載は表記差候補として扱い、同定が推定であることを該当期間・履歴に表示します。元の掲載名・適用日・判断理由・出典は失われません。表記揺れだけで架空の台移動日を増やさないための処理です。

## データの区分

2023-04-27以降を本番期間候補、それ以前を過去資料として区分します。日数や行数が多くても、連続日次データが揃ったとは判定しません。貸区分（貸メダルの単価区分）は扱いません。

## 保存先・更新

データはデータフォルダーの `GothamDataBase.sqlite`（GDB）、バックアップは同フォルダーの `backups`（`GothamDataBase-日時.sqlite`）、起動・通信ログは `application.log` です。ログに認証トークンは記録しません。

| OS | データフォルダー |
| --- | --- |
| Windows | `%LOCALAPPDATA%\JokersEye`（1.0 と同じ） |
| macOS | `~/Library/Application Support/JokersEye` |
| Linux | `~/.local/share/JokersEye` |

環境変数 `JOKERS_EYE_DATA` または `--data <フォルダー>` で変更できます。アプリを終了してから `git pull` で更新すると、同じデータを使用します。リポジトリフォルダーの削除では観測データは削除されません。Windows と macOS の間でデータを移す場合は、アプリを終了して `GothamDataBase.sqlite` をコピーしてください（WALファイルが残っている場合は混在させないでください）。

バックアップから復元する場合は、アプリを終了して既存データフォルダー全体を別名で退避したうえで、新しいデータフォルダーにバックアップを `GothamDataBase.sqlite` として配置します。古いWALファイルと混在させないでください。

コード署名・自動更新は未対応です。

## 構成と開発

`app/server.py`: Python標準ライブラリによるHTTP / SQLite。`web/map.js`: 期間選択と機種マップ。`web/map-history.json`: 根拠URL・日付・台番範囲・差分・欠落を持つ配置履歴。`app/desktop.py`: 専用ウィンドウと公開データ取得ブラウザー（Windows / macOS 共通）。`app/platform_support.py`: OS ごとの差（データフォルダー、エラー表示、外部ブラウザー）。`launch.py`: 仮想環境の準備と起動。`tools/collect_map_history.py`: 公開資料の収集と期間生成。`assets/`: アイコン原画と生成記録。

```bash
python -m unittest discover -s tests -v
node tests/test_floor_plan.cjs
node tests/test-source-readiness.cjs
node tests/test_juggler_preparation.cjs
node --test --experimental-test-coverage --test-coverage-include="**/juggler-math.js" tests/test_juggler_math.cjs
python app/desktop.py --data dev-data
python app/server.py --data dev-data --port 18764 --open
```

`tests/test_juggler_math.cjs` は比較用に `python3`（Windows は `python`）を呼びます。別のPythonを使う場合は環境変数 `PYTHON` で指定します。実ページ回帰用の小さなテーブル資料は `tests/fixtures/min-repo-bonuses.json` で、公開DOM資料から `python tools/reduce-source-fixture.py <capture.json> <fixture.json>` により不要な表を除いて再生成できます。

サーバー・スクレイパー・テストはPython標準ライブラリだけで動きます（追加パッケージは専用ウィンドウの pywebview のみ）。Pythonは3.12.10（`.python-version`）、検証用Node.jsは24.19.0（`.nvmrc`）。APIは127.0.0.1だけにバインドし、起動ごとのトークンを必須とします。通常の通信では外部サービスを使いません。
