# Joker's eye 1.3.1

ゴッサムシティの観測データと店内配置を研究する、Windows向けローカルアプリです。

## 作業ブランチの保存点

`feature/bbrb-scraper` は、手元の変更を保全する実装途中のチェックポイントです。BB・RB取得方式の改修と全ジャグラー解析の接続は未完了で、配布版として扱わないでください。進捗、既知のテスト失敗、次の作業は [docs/handoff.md](docs/handoff.md) に記録しています。

GitHubのmainには別途Windows/macOS共通のPython構成があり、このブランチとはまだ統合していません。今後の開発は目的ごとのブランチで行い、mainへ直接pushしません。既存Windows EXE・同梱runtimeは旧履歴として残っていますが、新しい配布バイナリ、実データ、ログ、秘密情報はコミットしません。

この保存点のPythonは3.12.10（`.python-version`）、検証用Node.jsは24.19.0（`.nvmrc`）。Pythonの業務ロジックとNodeテストは標準ライブラリだけを使用します。開発時はリポジトリのルートから `python -m unittest discover -s tests -v` と `node tests/test_floor_plan.cjs` を実行できます。macOSには同梱Windows runtimeを使用せず指定版のPython・Nodeを用意してください。専用デスクトップのmacOS起動・依存関係・ビルドは、main側の手順を統合してから対応します。

## 起動

ZIPをすべて展開し、`Joker's eye.exe` をダブルクリックします。Pythonのインストールは不要です。WebView2を内蔵した専用のWindowsウィンドウで開きます。店舗資料などの外部リンクだけを標準ブラウザで開きます。

必要環境：Windows 10/11 x64、.NET Framework 4.6.2以降、Microsoft Edge WebView2 Runtime。Runtimeがない場合は[Microsoft公式配布ページ](https://developer.microsoft.com/microsoft-edge/webview2/)からEvergreen Runtimeをインストールしてください。WebView2 SDK 1.0.3856.49のライセンスとNOTICEを `licenses` に同梱しています。

左下の「アプリを終了」またはウィンドウの×で専用サーバーも停止します。最小化中も接続を維持します。二重起動時は既存ウィンドウを手前に表示します。起動ごとに空きローカルポートと独立したセッションを使用します。

## タスクバーへのピン留め

旧版で登録したChromeのピンは一度「タスクバーからピン留めを外す」を選びます。0.3.3のEXEを開き、専用アイコンを右クリックして「タスクバーにピン留めする」を選んでください。以後はそのアイコンからJoker's eyeが起動します。展開先を移動するとピンの参照先が変わるため、利用するフォルダーを決めてからピン留めしてください。

プロセスとウィンドウのAppUserModelIDを `JokersEye.Desktop` に設定し、再起動先とアイコンをEXEに登録しています。[Windowsのアプリ識別の仕様](https://learn.microsoft.com/windows/win32/shell/appids)に従い、ショートカットにも同じ識別子を設定します。

初回起動時の稼働・差枚の観測データは0件です。別途、公開フロア図と、みんレポの公開日別台番表から作った機種配置履歴を同梱しています。対象の公開一覧は2023-04-27〜2026-09-29です。取得できた日数・期間数・最終確認日・未取得日は「機種マップ」に表示します。全台表を読めない日を配置確定済みとして補完しません。

店内マップは、現地確認済みのNumbered map 1.4 ex.Is-IDの固定配置を使用します。全310台の四角の位置・角度・台番号、32島の構成と内部Is-IDは変更せず、Is-IDの文字は表示しません。台番号で履歴と結び付け、期間タブや日付検索で各時期の機種を表示します。固定図を共通の土台として使うため、過去時点の壁・島形状まで確認したものではありません。

1.1.1では四角をすべて一律1.25倍に拡大し、重なっていた5台だけ島の中心から外向きに表示調整しています。この例外は別ファイルに記録し、上記の正本の位置は未変更です。台番号・角度・内部Is-IDは固定。黄色の変更マークの半径は以前の2倍。拡大・ドラッグは描画タイミングに集約し、画面外の台の描画を省略します。

1.2.0では、データ管理に「基礎データシート」を追加しました。初回の「CSVファイルを作成」はみんレポの2024-03-01〜2026-09-30を対象に、`日付、曜日、台番号、機種、ジャグラーかジャグラーじゃないか、ゲーム数、BB数、RB数、合成、差枚、出率`の11列でCSVを保存します。作成済みCSVは画面上で閲覧でき、日付・月・曜日・機種・ジャグラー判定・ゲーム数以上・差枚以上・合成1/n以下・出率以上を複合して絞り込めます。「不足分だけ更新」は現在の基礎データシートに存在しない日付だけを取得対象にし、既存日付の再スクレイピングを行いません。

四角は既存のデザインを流用し、機種マップではジャグラー系統を高彩度、その他を低彩度で色分けします。外壁はUI共通の青緑。クリック・キーボード選択、台番号・機種検索、変更台の強調、台番号別の履歴は保持しています。拡大縮小は＋／−、倍率スライダー、Ctrl＋ホイールで操作し、拡大中はドラッグで移動できます。「選択台へ」で選択中の台を拡大、「全体表示」で戻ります。期間切替でもカメラと選択台を保持します。記録にない機種は「未掲載」とし、現在の店舗とのリアルタイム同期は未実装です。

## ジャグラー設定推測機

左メニューの「ジャグラー設定推測機」から機種を選び、「設定別スペック」「ぶどう逆算機」「設定推測機」を切り替えます。北電子公式一覧の47製品・パネルを同梱し、設定1〜6のBB確率、RB確率、合成確率、出玉率を表示します。6号機と過去の5号機は区別しています。各表から公式スペック・配当表へ移動できます。旧5製品の公式表にないBB/RB別の値は「未掲載」です。

1.3.0はユーザー指示に従う関数準備版です。ぶどう逆算・設定別確率の関数と入力欄を用意していますが、実行ボタンは無効で結果は「未計算」です。入力や機種切替で計算は実行しません。既存CSVや観測への推測の適用も行いません。関数の入力、逆算条件、推測の定義は[docs/juggler-estimators.md](docs/juggler-estimators.md)を参照してください。

1.3.1では、追加の検算指示に従い、全47製品・パネルの関数を合成テストデータだけで実行検証しました。992件合格、計算モジュールの関数・行・分岐カバレッジ100%。入力検証と数値安定性の不具合を修正しています。画面の実行ボタンは無効のままです。[検証記録](docs/juggler-test-results.md)を参照してください。

## 公開データのスクレイピング

「データ管理」の「本日までのデータをスクレイプ」で取得します。初回は2023/4/27以降、次回は数値データの最終取得日の翌日から日本時間の本日までを追加します。通常更新で過去の失敗・未掲載日へ戻ることはありません。過去日を再試行する場合は「初回の取得範囲を指定」で開始日・終了日を明示します。重複は日付・台番号の主キーで防止し、手動で取り込んだ観測は上書きしません。終了や通信失敗までの結果はSQLiteとCSVに残り、次回再開できます。

アプリに組み込んだ通常のWebView2ブラウザーで公開ページを読みます。日別レポートを先に開き、その本文にある正規の全台データ一覧リンクをたどります。日付・店舗名・掲載年月日・台番号を検証してから保存します。取得ブラウザーは画面に表示され、閉じると取得を停止します。OpenAI API・Codex・AIモデルは呼び出さないため、通常の更新でAIトークンは消費しません。全台表は逐次取得で1秒以上、BB/RBの機種別ページは3秒以上の間隔を設けます。HTTP 200の空ページだけは3秒待って通常の再読み込みを一度行います。401/403/429、認証・CAPTCHA等に対して回避処理は行いません。データ提供サイトの変更や閲覧制限がある場合、取得できるとは保証しません。

通常の取得対象はみんレポの当日全台表に公開された機種・台番号・G数・差枚・出率です。「BB・RBも取得」を選択すると、全台表にある各機種へのリンクを追加巡回し、機種別の台番表からBB/RBをまとめて取得します。個別台を一台ずつ巡回する必要はありません。既に全台表を取得した日でも、BB/RB追加巡回が未完了なら対象に含めます。BB/RBの出典はCSVのbonus_source_urlに残します。機種数に応じて取得時間が増えるため、基礎データシートの初回作成・不足分更新は、まず全台表だけを日単位で完走させます。追加のBB/RB取得が失敗しても、その日を記録して後続日へ進み、全台表の欠けを作りません。日別の通常取得失敗も日付単位で記録して次の対象へ進みますが、HTTP 401/403/429のアクセス制限だけは停止します。差枚の「−」も欠測です。0を補完せず空欄で保存し、欠測件数を表示します。貸区分は当日の根拠がないためunknownです。「complete」は番号の全台網羅を意味し、全数値項目の網羅ではありません。

CSVは `%LOCALAPPDATA%\JokersEye\exports` に保存され、アプリからもダウンロードできます。`gotham-city-開始日_終了日.csv` が取得済み数値データ、`coverage-開始日_終了日.csv` が全暦日の取得状況です。公開一覧にない日を休業日や全台0とは断定しません。既存の機種名だけのキャッシュは数値データ取得済みとは扱いません。

基礎データシートは `jokers-eye-base-data-2024-03-01_2026-09-30.csv` として同じexportsフォルダーに保存されます。初回作成後は、データ管理の「不足分だけ更新」から不足日だけを追加できます。公開されていない日や取得できなかった項目は、欠測として残し0を補完しません。

## マップ操作

1. 左メニューの「店内マップ」を開くと、最新の確認済み配置を表示します。
   同じ画面の「台番号マップ／機種マップ」で表示を切り替えます。台番号マップは番号だけの共通色表示、機種マップは機種名と機種別の色を表示します。期間・選択台を引き継ぎ、両表示の検索条件はそれぞれ保持します。表示位置は現地確認済みの固定図と、上記の重なり回避用表示調整を使用します。
2. 横並びの期間タブを押すか、期間名の `▽` から別の期間を選択します。期間は実際に台番への機種割当が変わった記録から生成しています。例として示された日付は境界に使っていません。
3. 「日付から探す」で確認したい日を選べます。その日の記録があれば該当期間の機種マップへ切り替わり、未取得・未掲載日なら「未確認」を表示します。
4. 台番号を押すと、その番号に割り当てられていた機種の変遷と出典を表示します。履歴の期間名から、その当時のマップへ戻れます。
5. 「変わった台だけ強調」と「配置変更」の一覧で、変更前後の機種・台数増減を確認できます。機種名・台番号による検索も使えます。

期間は開始日を含み、終了日を含みません。前日と当日の台番表が揃う変更日は「前日との差分で確認」、欠落を跨ぐ差分は「変更日未確定・初確認日」と表示します。同じ配置が再確認された場合は新しい期間を増やさず、欠けた日を保持します。機種マップの期間が表示されることと、期間中の全日を確認できていることは別です。

DMMぱちタウンの新台・増台・入替告知も収録し、確認した実施日と同じ配置変更に出典リンクを付けています。告知の掲載日だけが分かる場合は実施日に置き換えません。同じ機種の個体番号は公開表にないため、ここでいう台移動は台番号への機種割当の変化です。

掲載名の省略・型式名表記は、明示した個別ルールで比較上統合します。93–95番台の「ジャグラーガールズ／SS」の反復記載は表記差候補として扱い、同定が推定であることを該当期間・履歴に表示します。元の掲載名・適用日・判断理由・出典は失われません。表記揺れだけで架空の台移動日を増やさないための処理です。

## CSV

データ管理画面から空のテンプレートをダウンロードできます。

```csv
date,seat,model,games,bb,rb,net,rate
```

`date`: YYYY-MM-DD。`seat`: 台番号（文字列）。`model`: 機種名。`games`, `bb`, `rb`: 非負整数。`net`: 差枚（負数可、不明は空欄）。`rate`: `main`（主貸区分）/ `low`（低貸）/ `unknown`（未確認）。

登録済みの日付・台番号と重複した場合、または不正な行がある場合はファイル全体の取込を中止します。既存のレコードを上書きしません。1回のファイルは9MB以下です。機種名や貸区分の正しさ、全台網羅性は利用者が確認します。

2023-04-27以降を本番期間候補、それ以前を過去資料として区分します。日数や行数が多くても、連続日次データが揃ったとは判定しません。`main`は1枚当たりの貸価格を正確に表すものではなく、詳細な貸条件は今後設置履歴へ追加する予定です。

## 保存先・更新

データは `%LOCALAPPDATA%\JokersEye\jokers-eye.sqlite3`、バックアップは同フォルダーの `backups`、起動・通信ログは `application.log` です。ログにCSV本文・認証トークンは記録しません。アプリを終了してから新しいZIPを別フォルダーへ展開すると、同じデータを使用します。アプリフォルダーの削除では観測データは削除されません。

バックアップから復元する場合は、アプリを終了して既存データフォルダー全体を別名で退避したうえで、新しいデータフォルダーにバックアップを `jokers-eye.sqlite3` として配置します。古いWALファイルと混在させないでください。

`Create shortcut.ps1` は任意のデスクトップ・スタートメニューショートカット作成用です。既存のJoker's eye用ショートカットは現在のEXEへ更新し、アプリ識別子も登録します。実行する場合は展開先を移動しないでください。コード署名・自動更新は未対応です。

## 構成と開発

`app/server.py`: Python標準ライブラリによるHTTP / SQLite。`web/map.js`: 期間選択と機種マップ。`web/map-history.json`: 根拠URL・日付・台番範囲・差分・欠落を持つ配置履歴。`launcher/Launcher.cs`: Windows起動ランチャー。`build.ps1`: アイコン変換とランチャービルド。`tools/collect_map_history.py`: 公開資料の収集と期間生成。`assets/`: アイコン原画と生成記録。

```powershell
.\runtime\python.exe -m unittest discover -s tests -v
node tests\test_juggler_preparation.cjs
node --test --experimental-test-coverage --test-coverage-include="**/juggler-math.js" tests\test_juggler_math.cjs
.\runtime\python.exe app\server.py --data .\dev-data --port 18764 --open
powershell -File .\build.ps1
```

開発時にもPython追加パッケージは不要です。APIは127.0.0.1だけにバインドし、起動ごとのトークンを必須とします。通常の通信では外部サービスを使いません。`runtime/LICENSE.txt` は同梱Pythonのライセンスです。

JavaScriptの開発テストにはNode.js 22以降を使用します（アプリの通常利用には不要）。数値テストの比較用Pythonは同梱runtimeを使用します。
